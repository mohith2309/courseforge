## 2024-05-15 - Entitlement Spoofing & Admin Token Leakage
**Vulnerability:** The application blindly trusted client-provided status (e.g., `pro: true`) in `/me/claim` and exposed an insecure `/me/pro` route allowing arbitrary entitlement elevation. Furthermore, the `isAdmin` check permitted the admin token to be supplied via a URL query parameter (`?adminToken=...`), which can be leaked in server logs, browser histories, and referer headers.
**Learning:** Client-provided billing signals and entitlement statuses must never be trusted. The server must be the source of truth for pricing and user entitlements. Additionally, sensitive credentials like admin tokens must never be sent via URL query parameters.
**Prevention:** Always validate content attributes (like course prices being 0 for free claims) against the server-side datastore (`published` in this case). Restrict sensitive operations to secure custom headers (e.g., `x-admin-token`) instead of URL query parameters.
