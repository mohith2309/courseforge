## 2026-06-22 - Fail-Closed Secret Initialization & URL Query Token Leakage
**Vulnerability:** The application was failing "open" by allowing the backend server to start in a production environment with default developer secrets (`dev-secret` and `admin-dev`). Furthermore, the `isAdmin` check permitted `adminToken` to be passed as a URL query parameter, leading to token leakage in browser history, referer headers, and server logs.
**Learning:** A missing proactive check at application initialization allowed default secrets to persist into production deployments, fundamentally breaking signature verification and authentication schemes. Secondly, allowing sensitive tokens to be passed via URL paths is a critical design flaw because URLs are inherently insecure transmission channels for secrets (logged broadly across network layers).
**Prevention:** Implement strict fail-closed application initialization checks: immediately abort the startup sequence (`process.exit(1)`) if required secrets are missing or match insecure default values in production. Always mandate that sensitive tokens (like admin keys) be transmitted strictly via custom HTTP headers (e.g., `x-admin-token`), never as URL query parameters.
