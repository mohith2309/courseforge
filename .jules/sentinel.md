## 2025-06-15 - Auth Bypass via Unvalidated Input in Claim Endpoint
**Vulnerability:** The `/me/claim` endpoint (intended to migrate local device purchases/pro status to an authenticated user account) allows any signed-in user to freely grant themselves "Pro" status and arbitrary course entitlements by simply sending `{"pro": true, "courseIds": ["any_course_id"]}`. It does not verify if the courses claimed were actually free, or whether the user had a legitimate prior entitlement. The endpoint implicitly trusts the client's assertion of ownership.
**Learning:** Guest-to-user migrations must strictly validate entitlements on the server-side against an independent source of truth (like receipt validation or price checks), rather than blindly accepting client-provided lists. The current system was previously hardened to block `pro` status claims and only allow claiming free courses (`priceInr === 0`), but that hardening appears to have been lost or bypassed.
**Prevention:** Re-implement server-side validation. Enforce that only free courses can be claimed via the generic `/me/claim` sync. Remove the ability to claim `pro: true` via this endpoint. Paid courses and Pro status must always go through the authoritative `/payments/verify` flow.
