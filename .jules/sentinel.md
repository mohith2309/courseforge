## 2024-06-17 - Fix entitlement spoofing in claim endpoint
**Vulnerability:** The application had an endpoint (`/me/pro`) that allowed any authenticated user to grant themselves "Pro" status without verification or payment. Furthermore, the guest-to-account migration endpoint (`/me/claim`) blindly trusted the client-provided list of claimed course IDs and boolean `pro` status, allowing users to spoof ownership of premium courses or a Pro subscription.
**Learning:** Client-provided entitlement state or billing signals (e.g., passing 'pro: true' or an array of claimed course IDs) must never be blindly trusted. The source of truth for pricing and user entitlements must always reside and be validated on the server.
**Prevention:** Remove endpoints that blindly trust client entitlement assertions. When merging guest state (like claimed courses), the server must cross-reference the requested IDs with the catalog datastore to verify the items exist and are genuinely free (`priceInr === 0`) before adding them to the user's entitlements. Pro subscriptions must strictly be processed through verified payment flows.
