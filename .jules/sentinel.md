## 2024-05-15 - Unhandled Exception DoS via `crypto.timingSafeEqual` and Multi-Byte Characters
**Vulnerability:** A Denial of Service (DoS) vulnerability existed in `verifyToken` and `safeEq` functions because they compared string lengths rather than buffer byte lengths before invoking `crypto.timingSafeEqual`. This allows an attacker to supply a token or string with the same string length as the expected value but a different byte length (using multi-byte characters like emojis or unicode), causing Node.js to throw an unhandled `RangeError` (Input buffers must have the same byte length) which crashes the server.
**Learning:** `crypto.timingSafeEqual` is strictly strict about buffer lengths; any mismatch throws a hard exception. String lengths (`.length`) do not directly correspond to byte length when strings contain multi-byte characters.
**Prevention:** Always convert inputs to `Buffer` first, then explicitly verify `buffer.byteLength` on both buffers before calling `crypto.timingSafeEqual`.
