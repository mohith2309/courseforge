## 2024-06-19 - Admin Token Leakage & Entitlement Spoofing
**Vulnerability:** The `/me/pro` endpoint allowed unauthenticated/unauthorized users to blindly grant themselves "Pro" status. The `/me/claim` endpoint similarly trusted client-provided `pro: true` signals and lacked server-side verification of course prices, allowing users to claim paid courses for free. Additionally, the `isAdmin` function accepted the `adminToken` via a URL query parameter, which is a significant token leakage risk in logs, browser history, and referer headers.
**Learning:** Client-provided billing signals and entitlement claims (e.g., `pro: true` or requesting arbitrary course IDs) must never be trusted. The source of truth for pricing and user entitlements must always reside and be validated on the server. URL query parameters should never be used for sensitive tokens.
**Prevention:** Always validate requested content attributes (like price) against the server's authoritative datastore before granting entitlements. Prefer custom headers (e.g., `x-admin-token`) over query parameters for authentication tokens to prevent accidental leakage. Ensure security gates fail-closed.
