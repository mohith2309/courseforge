## 2024-05-24 - `timingSafeEqual` Denial of Service via Byte Length Mismatch
**Vulnerability:** The application used `a.length !== b.length` (string character length check) before calling `crypto.timingSafeEqual(Buffer.from(a), Buffer.from(b))`. An attacker could pass a string with the same character length but a different byte length (e.g., using multi-byte characters like emojis). `timingSafeEqual` strictly requires matching *byte lengths* and throws an unhandled exception ("Input buffers must have the same byte length") when they differ, completely crashing the Node.js process (Denial of Service).
**Learning:** Checking string `.length` is unsafe when converting to Buffers because multi-byte characters inflate the Buffer byte length without affecting the string length. Unhandled `timingSafeEqual` exceptions bring down the entire server.
**Prevention:** Always cast inputs to Buffers first and check their `byteLength` explicitly (`bufA.byteLength !== bufB.byteLength`) before calling `crypto.timingSafeEqual()`. Implement a robust `safeEq` utility function for all secure comparisons to abstract this safely.
